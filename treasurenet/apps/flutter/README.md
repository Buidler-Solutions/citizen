# TreasureNet Mobile App (Flutter)

The player client for TreasureNet Citizen Edition. Players use this native
app exclusively; Game Masters run the web console (`apps/web`) and approve
claims from there. The app is built with the same stack as the monorepo's
`wallet/mobile` (Riverpod + GoRouter + flutter_secure_storage +
`cryptography` Ed25519).

## Status

Implemented and green: `dart analyze` clean, `flutter test` passes
(including a byte-exact Ed25519 parity test against the node chain SDK),
and the debug APK builds for Android.

```bash
cd treasurenet/apps/flutter
flutter pub get
dart analyze
flutter test
flutter build apk --debug

# Run against a local backend. 10.0.2.2 reaches the host loopback from the
# Android emulator; the iOS simulator can use 127.0.0.1 directly.
flutter run --dart-define=TREASURENET_API=http://10.0.2.2:7755
```

## Screens

1. **Onboarding** - generate the device Ed25519 keypair, show the DID,
   register the wallet (`POST /wallet/register`)
2. **Login** - challenge-response: sign `treasurenet-login:<nonce>` with the
   key held in secure storage (iOS Keychain / Android Keystore)
3. **Hunt list** - active hunts with reward, expiry, status; consent banner
   when no valid consent receipt exists
4. **Hunt detail / clue flow** - sequential clue chain with lock state from
   `GET /games/:id/progress`; check-in submits the live GPS fix and shows
   the unlocked manifest id
5. **Claim** - capture photo proof, submit `POST /games/:id/claim/request`,
   then poll while the GM approves from the web console; confirmation shows
   the finality receipt (receipt id + block height + reward)
6. **Wallet** - CTZN balance, finality receipts, notifications
7. **Consent** - location/photo consent receipt status and re-grant

## Claim flow (mobile player + web GM)

The claim messages must be signed by the Game Master over the winner's DID,
so the player app never holds GM keys. The mobile flow is:

1. Player captures photo proof at the final clue and submits a claim
   request (`POST /games/:id/claim/request`, player session).
2. The request appears in the GM console's "Pending player claims" panel.
3. The GM approves; the browser signs
   `claim:<hunt_id>:<player_did>` and `claim:<escrow_id>:<player_did>`
   with the GM key and posts them with the `request_id`.
4. The backend adds the oracle co-signature (2-of-2), executes both
   module claims, credits the CTZN balance, and records the finality
   receipt. The app polls and displays the receipt.

## Crypto parity

All surfaces sign identical canonical strings with identical key formats
(raw 32-byte Ed25519 seeds, lowercase hex signatures, DIDs as
`did:key:ed25519:<pubhex>`). The app signs only:

- login: `treasurenet-login:<nonce>`

Everything else is service-sponsored (builder credits). Parity is enforced
by `test/crypto_parity_test.dart`, which asserts a signature generated by
the node chain SDK (`chain/sdk`) byte for byte.

## What changes versus the Stellar original

| Original (Stellar) | Citizen port |
|---|---|
| Stellar keypair (G.../S...) generated on device | Ed25519 keypair generated on device, DID = `did:key:ed25519:<pubhex>` |
| Secure enclave stores Stellar seed | flutter_secure_storage stores the raw Ed25519 seed (32 bytes) |
| Sep10-style challenge auth | `POST /auth/challenge` then sign `treasurenet-login:<nonce>` |
| Built-in wallet sends XLM transactions | Backend-sponsored chain writes via builder credits; app only signs messages |
| Claim screen shows Stellar tx hash | Finality receipt: receipt id + block height + commit proof |
| Clue payloads fetched from backend DB | Encrypted file store manifests (on-device decryption is a tracked gap) |
| GM co-located in player app flow | GM approval lives in the web console; mobile strictly a player app |

## Notes and known limits

- GPS anti-spoof gating is a sanity check (rejects impossibly exact or very
  coarse fixes); mock-location and accelerometer heuristics from the
  original app are a tracked gap (`docs/GAP_ANALYSIS.md`).
- Map UI is a list/compass-style presentation; a full flutter_map surface
  is a tracked gap.
- Clue text decryption on-device (via the encrypted file store) is a
  tracked gap; unlocked clue manifest ids are displayed today.

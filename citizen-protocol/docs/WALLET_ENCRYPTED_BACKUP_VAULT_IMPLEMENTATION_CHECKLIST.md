# Wallet Encrypted Backup Vault Implementation Checklist

## Purpose

Define an implementation-first plan for adding a **wallet encrypted backup vault toolset** to the monorepo. The toolset is intended to protect wallet credentials generated by, with a primary deployment target of removable USB media:

- `wallet/cli`
- wallet browser extension surfaces

This plan targets a **multi-vault decoy model** (VeraCrypt-style behavior) with at least:

1. **Decoy vault** for low-sensitivity data and plausible-deniability workflows.
2. **Critical vault** for confidential wallet secrets and high-impact recovery material.

> Scope note: this checklist defines implementation checkpoints and acceptance criteria. It does not claim production security until formal review and threat-model sign-off are complete.

---


## Product Intent: VeraCrypt-Style USB Vault (Replicate + Innovate)

This initiative should replicate key VeraCrypt-style operating properties while adding Citizen-specific wallet recovery ergonomics:

- **Replicate**
  - Multi-slot encrypted vault behavior with decoy + critical separation.
  - USB-portable encrypted container workflows for offline custody.
  - Strong passphrase-gated access with tamper-detecting restore verification.
- **Innovate**
  - Wallet-aware backup scopes (identity keys, account keys, consent artifacts) with deterministic restore sequencing.
  - Builder/operator automation hooks through CLI JSON outputs and runbook-driven recovery checks.
  - Extension-safe encrypted export/restore paths aligned to browser runtime constraints.

> Security language constraint: avoid terms like “military-grade” in implementation and user docs. Use concrete primitives, parameter choices, and verified test outcomes instead.

## High-Level Design Constraints

- Governance-first and builder-first: integrate cleanly with existing wallet/runtime workflows and deterministic recovery expectations.
- Explicitly non-speculative: deliver practical wallet backup security, not token/economic behavior.
- User-custody aligned: encrypted backup material remains user-controlled; no plaintext credential escrow in protocol services.
- Backward-compatible migration path for existing wallet CLI and extension users.
